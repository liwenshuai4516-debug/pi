# UI 测试能力实施计划书

更新：2026-10-21。状态：**正在按任务依赖实施**。UI-01 至 UI-09 已完成；各任务状态和证据以本文登记为准。本文统一维护实现顺序和进度；能力规则见 [UI 详细设计](./UI测试业务流程详细设计.md) 与 [录制及资产复用设计](./UI自动录制与资产复用设计.md)。

## 1. 实现目标与边界

首个可用版本支持：用户给出一个模块的测试目标 → Agent 自动操作录制 → 按模块/功能生成用例与有依据的断言 → 独立设计评估及有限修订 → 保存获批资产 → 从干净初始状态执行 → 程序统计真实结果 → Agent 分析失败 → 独立结果评估 → 交付报告。完全退出并重开客户端后，可以直接执行原资产，也可以只分析旧批次，不再完整生成一遍。

首期限定一个测试环境、一个浏览器项目、一个主链及关键校验；串行执行即可。源码输入和浏览器输入都支持，但只有源码时交付设计草稿，不假称已录制或运行。没有需求时允许明确声明校验、行为基线测试，不自行补造业务预期。

首期不做接口测试平台、全站自动遍历、视觉回归平台、多 Agent 并发调度、后台无人值守、通用工作流引擎或新任务管理界面。独立评估是首期必需能力，评估角色可以顺序运行，不要求多个 Agent 同时工作。

## 2. 架构与复用约束

| 能力 | 首选实现 | 必须守住的边界 |
|---|---|---|
| 浏览器发现与自动录制 | Playwright 官方 planner/generator 方法与测试 MCP，先实际验证 | 一个浏览器后端；通用 MCP 不默认具备 generator 工具 |
| 脚本执行与证据 | Playwright Test、fixture、reporter、trace | 不自建执行器，不用聊天结论替代断言结果 |
| 能力加载与分发 | 现有 Pi Skills、资源加载、原生 MCP；一个项目自有 Pi package | 不再开发 MCP 适配层；Agent 按需选能力，脚本强制执行门禁 |
| 评估 | 独立上下文、受限工具的 reviewer 角色 | 不把同上下文自审称作独立评估，不将两次同意视为事实证明 |
| 测试资产与任务 | 项目文件、成熟 JSON Schema 校验器、原子提交、对象锁 | 单一权威 manifest；索引可重建，不先引入数据库服务 |
| 客户端执行核心 | 现有 `pi-agent-core.Agent` | 不改用 `AgentSession` / `createAgentSession`，不自建 Agent 执行循环 |

既有 Pi 会话仍由 `SessionManager` JSONL 辅助模块保存；`qa/ui/` 保存测试业务数据，二者不互相替代。`pi-subagents` 的内部架构与桌面兼容性尚未验证，不能作为已可用前提。项目目前安装的 Playwright 版本为此前检查到的 1.62.1，实施时重新核对并记录锁定版本。

建议落点如下；均为未来目录约定，本次不创建空壳：

| 归属 | 建议位置 | 内容 |
|---|---|---|
| 项目自有测试能力包 | `packages/ui-testing/` | package 元数据、Skills、schema、薄脚本与模板；不增加第二个应用 |
| 能力包内部实现 | 上述包内 `src/` | TypeScript；先划分资产/任务存储、门禁与 runner、结果解析三个职责，按实际需要增文件 |
| 自动化验收 | `tests/ui-testing/`、`tests/support/` | 流程测试、受控页面、错误样本；与真实业务测试结果分开 |
| 被测项目资产 | 被测项目的 `qa/ui/` | recordings/assets/tasks/runs，不写入 Skill 安装目录 |
| 必要客户端接入 | 既有 `main/agent`、`main/plugins` 等所属模块 | 只补真实缺口，不把测试流程堆入 `agent-host.ts` 或 renderer |

若实际需要新增 IPC，才同步 `shared/types.ts`、preload、`main/ipc/register.ts` 并校验来源和参数。优先通过现有聊天、插件及 MCP 界面完成操作。扩展的系统权限不能被描述为已受内置文件沙箱限制，reviewer 的工具集合要实际限制。

### 2.1 成熟能力优先与最小自建约束

以下约束适用于 UI-01 至 UI-14 的设计、实现和验收。目标是在满足功能、可靠性和现有架构的前提下，减少新增代码、接入工作和长期维护成本；不能以依赖数量或自研代码量作为交付成果。

| 优先顺序 | 优先复用的能力 | 实施要求 |
|---|---|---|
| 1 | 当前项目已有能力、Pi 原生 SDK、已安装且可用的扩展/包/Skills/MCP | 先盘点源码、依赖、工具清单和实际调用入口；可满足需求就直接组合使用 |
| 2 | Pi 生态中成熟的扩展、包、Skills、MCP server | 优先官方及持续维护、文档和使用证据明确的项目；核对当前 Pi/桌面环境兼容性，不因名称匹配就认定可用 |
| 3 | 成熟的测试框架、通用库、组件库与开源项目 | 复用 Playwright 等现成执行、录制、断言、报告能力；校验、锁、解析、界面组件同样先查现有库 |
| 4 | 项目特有的 Skill 规则、配置和薄适配 | 只补输入输出映射、版本绑定、业务门禁和证据关联等缺口，保留上游入口与升级路径 |
| 5 | 最小自建实现 | 仅在候选能力不能满足具体需求，或接入/维护成本明显更高时采用；记录证据、取舍和实现边界 |

这些能力是组合关系，不要求把同一功能同时封装成扩展、包、Skill 和 MCP。已有工具可直接调用时，不额外套服务或再建一层通用框架；薄适配也不复制上游执行器、调度器、协议和组件源码。

**允许主动联网搜索与查阅公开资料。** 每项任务先检索本项目与已安装能力；需要补能力或确认版本时，可自行搜索 Pi 官方文档、包说明、上游仓库、发布记录和相关 issue，无需逐次请求搜索许可。检索只包含必要的公开技术信息，不上传凭据、私有源码或业务测试数据。联网不可用时使用本地资料并标注待核实项，不把未搜索到当作生态中不存在。

选型依据至少包括：官方来源或仓库链接、核对日期与版本、维护状况、许可证适用性、核心功能、当前架构兼容性、接入及后续维护成本。对影响主链的候选做最小真实调用验证；搜索摘要、star 数、安装成功和示例截图不能代替可用性证据。不要求为每个小改动重新比较全部生态，已有有效选型记录可复用。

**需要新增界面时优先使用已有组件或成熟组件库。** 表格、表单、弹窗、树、代码/报告展示等，先复用项目已有组件；不足时优先评估与当前原生 DOM + TypeScript 兼容的库或 Web Components。复用已有主题和交互，检查必要的可访问性、体积及 Electron CSP 兼容性；不为使用某个组件库迁移 React/Vue，也不同时引入多套重叠组件体系。简单现有控件已满足需求时继续复用。P0 仍通过现有聊天和扩展入口交付，不因组件库要求新增管理界面。

后续开发每项任务需在实施记录中简要填写：`需求能力 → 复用来源/版本 → 验证证据 → 剩余缺口 → 最小新增代码范围`。如选择自建，再写明候选不适用的具体原因；无缺口说明而重复实现成熟能力的任务不能标记已完成。此记录直接附在本文第 7 节的任务证据中，不另建选型平台或审批流程。

### 2.2 各阶段复用清单与编码前检查

下表是选型顺序，不能作为能力已安装、兼容或通过验证的证明。具体版本及可调用入口沿用任务证据，升级或替换时只复核受影响部分。

| 任务阶段 | 先检查和复用 | 项目仅补的内容 |
|---|---|---|
| UI-01、UI-02 能力接入 | Pi 资源加载、package 元数据、扩展工具注册、原生 MCP 发现和连接 | 测试能力声明、输入输出契约和必要入口 |
| UI-03、UI-04 资产与环境 | 已有文件锁、schema 校验器、Playwright fixture、独立 context、认证状态引用 | 资产修订及引用规则、项目环境与数据归属约定 |
| UI-05 自动发现与录制 | 已有路由/组件元数据和测试；实际可用的 Playwright planner/generator、MCP 快照与操作日志 | 业务目标、探索边界、模块映射和录制来源关联 |
| UI-06 用例与设计评估 | 可用 Skills、官方测试生成方法、Playwright 原生定位器/expect、TypeScript 检查、既有 Agent 独立上下文 | 有来源的用例/断言映射、评估规则与程序门禁 |
| UI-07、UI-08 执行与报告 | Playwright Test CLI、配置、worker、reporter、trace 和 HTML 报告 | 批次与 case 关联、统计对账、失败归因和报告评估 |
| UI-09 至 UI-12 复用与维护 | Pi 按需资源加载、现有资产索引、Git 差异、Playwright 筛选执行 | 失效判定、阶段选择、恢复核对和证据生命周期 |
| UI-13、UI-14 并行与扩展 | Playwright 原生 worker/projects；经兼容验证的 Pi 多 Agent 扩展或包 | 账号/数据隔离和调度边界；不自建通用调度框架 |
| 确有需要的界面 | 现有组件、Playwright 原生报告；不足时评估兼容的成熟组件库 | 最小业务交互和主题适配，避免重写报告查看器或通用控件 |

每项任务开始编码前，按以下顺序检查，并将结论附在该任务的证据记录中：

1. 找到当前项目和已安装能力的实际入口；已有能力满足需求时直接使用。
2. 存在缺口时查询成熟候选，必要时联网查证；比较直接调用、配置组合、薄适配与自建的总体成本，包括依赖体积、兼容工作和长期维护。
3. 对选定主链做一次最小真实调用；已有同版本、同入口、同运行条件的有效证据可复用，不重复搭建验证工程。
4. 列出仍需新增的代码及其对应缺口，再进入实现。设计评估检查此对应关系；不能仅因 Agent 容易生成代码就选择自建。

优先采用一个能力覆盖多个阶段、按需加载的组合。仅因任务被拆成多个 Skill，不要求为每个 Skill 安装独立依赖、启动独立服务或创建新 Agent。联网查证也不等于安装或升级授权；本次任务若仅修改设计文档，则记录候选与验证计划即可。

### 2.3 选型记录模板与设计验收

后续任务直接在第 7 节对应任务记录中填写以下内容；可引用已有有效证据，无需另建文档或审批环节：

```text
任务 ID / 需求能力：
已有能力及实际入口：
选定复用来源 / 版本 / 官方链接：
兼容验证及证据引用（未验证则写明）：
剩余缺口及最小新增代码：
如需自建：成熟候选不适用的原因及成本比较：
如需界面：复用组件 / 组件库；与当前技术栈、主题及 CSP 的兼容结论：
```

设计验收时检查以下事项，未满足则补齐或缩减方案，不直接进入对应实现：

- **已有能力优先**：能直接调用的 Pi 扩展、包、Skill、MCP 或项目能力已有明确入口；不以重新实现作为默认方案。
- **自建范围可解释**：每项新增模块都对应已记录的缺口；不重复建设通用录制、浏览器控制、断言、执行、报告或调度能力。业务门禁和证据绑定仍须满足原有验收标准。
- **组件复用可落地**：确需界面时先复用现有组件及原生报告；新增组件库说明必要性和兼容性，避免重写通用控件。没有界面需求则填写“不适用”。
- **成本结论有依据**：比较接入配置、适配代码、额外服务和维护负担；可以用有依据的定性比较，不强求虚构工时。预计收益与实测数据分别记录，不能仅因引入成熟库就宣称已降低成本。

本节约束后续选型与实施；不要求为补齐记录而重写已验证可用的实现。上游版本、调用入口或运行条件变化时，重新核对受影响的记录与证据。

## 4. P0 任务说明

### UI-01 接入可行性与版本锁定

- **依赖/输入**：无前置任务；读取现有 Agent、扩展、MCP 和权限代码。使用隔离配置目录、可控测试页面和可用模型配置，不更改用户真实配置。
- **选型前置**：按第 2.1 节盘点已有能力，必要时联网检索成熟 Pi 扩展/包/Skills/MCP 及测试工具；输出可复用能力清单和最小缺口，优先验证可直接接入的方案。
- **工作范围**：验证测试 MCP 在 Pi 中实际发现工具，完成 setup → 浏览器交互 → 读取日志 → 写出测试草稿；验证既有资源加载能调用 Skill。另验证一个独立 reviewer 上下文只获得来源、候选和必要只读工具，能输出结构化评估。
- **交付物**：版本/启动配置记录、工具及副作用清单、最小真实动作和生成脚本证据、评估上下文隔离记录、选型决策与已知限制。
- **验收**：动作与日志、脚本逐项对应；不靠人工驱动完成示例路径。通过现有 SDK 的直接 Agent 能力或现有兼容入口实现独立评估，不引入 AgentSession 代管执行。取消与工具失败可识别，不能假称成功。
- **阻塞处理**：测试 MCP 不通时先定位差距，再评估单一替代路线；真实模型账号不可用时可用协议 fixture 验证接线，但真实录制/模型评估验收保持待验证。独立上下文不可用时登记最小接入缺口，不以同上下文自审关闭任务。

### UI-02 最小产物契约与能力包入口

- **依赖/输入**：UI-01 的可用工具、角色方式和锁定版本。
- **工作范围**：建立一个可被现有 Pi 资源加载的项目包；定义范围、来源、录制、case/assertion、资产 revision、设计评估、task、run、证据与报告的最小 schema。为能力声明输入/输出版本、工具需求、副作用和错误类别。
- **交付物**：包元数据和最小可调用入口、schema、各一份最小有效/无效样例；暂不创建没有实现的 Skill 空壳。
- **验收**：成熟校验器拒绝缺必需字段、未知主版本、无效引用；区分资产批准、任务完成和测试通过。断言有来源类别和版本，评估绑定候选摘要。共享契约不包含聊天全文、凭据值或临时浏览器句柄。
- **阻塞处理**：字段有歧义先用一条主链校验必要性；不提前设计通用 DSL。某角色输出不兼容时返回结构化错误及产物引用，不悄悄降级。

### UI-03 资产、任务和批次持久化

- **依赖/输入**：UI-02 的 schema；复用现有锁能力，缺失时选择成熟小型库。
- **工作范围**：实现 recordings/assets/tasks/runs 分层、不可变修订、依赖摘要、可重建索引、对象锁与完成标记。登记 task/run 后再启动后续操作；阶段记录输入摘要和产物引用。
- **交付物**：存取及校验脚本、重建索引入口、持久化样例和故障检查。
- **验收**：进程退出后可读取原资产/评估；索引缺失可重建。模拟多文件写到一半中断，半成品不可获批/执行。修改脚本或共享 fixture 均使原摘要校验失败；同一启动请求不创建两个活跃批次。
- **阻塞处理**：损坏对象隔离并保留原因，不自动从头录制；无法确认旧 run 是否结束则拒绝重复启动并要求核对。此阶段只做安全阻断，完整自动续跑留到 UI-11。

### UI-04 环境、认证引用及测试数据生命周期

- **依赖/输入**：UI-02；真实目标验收前需要测试地址、角色/凭据引用、允许操作范围、数据准备/清理约定。前期使用隔离受控页面继续开发。
- **工作范围**：预检站点、身份、初始状态与依赖；复用 Playwright fixture、独立 context 和现有数据准备方式。登记数据归属、业务键、生成规则、期限和清理状态；共享资源串行。
- **交付物**：环境配置模板、认证引用规则、数据 fixture 及生命周期记录、预检输出。
- **验收**：登录失效返回具体阻塞；连续两次运行得到独立数据；取消/失败仍有清理尝试及残留记录。凭据不进入普通资产/报告，录制遗留对象不被当作新 run 的初始数据。
- **阻塞处理**：不能隔离的数据禁用并行；没有可靠清理方式时按约定保留并报告，不删除未知归属对象。准备失败不计为业务断言失败。

### UI-05 发现模块并自动录制

- **依赖/输入**：UI-03、UI-04；范围、目标与源码或页面。
- **工作范围**：实现 `ui-discover-record`；读取相关路由/组件/已有测试或页面快照，建立模块—功能—场景清单；自动执行目标动作并保存日志、观察和草稿。设置步骤/时间及无进展停止条件。
- **交付物**：inventory、原始 recording、脚本草稿、初始状态/数据规则、未探索清单。
- **验收**：真实交互可追溯；脚本没有临时 ref、固定录制数据 ID 或个人路径。达到目标仍须检查可重建初始状态、数据替换、稳定定位、断言待补项和清理归属。只有源码时生成带来源草稿并标记未录制；只有浏览器时明确角色及可见范围。
- **阻塞处理**：不可访问页面、验证码、未获授权动作或无进展分支停止并保存局部产物；人工补充只针对必要步骤，不把人工全程操作称为自动录制。

### UI-06 用例、断言生成及设计评估门禁

- **依赖/输入**：UI-05；原始来源、录制草稿和 schema。
- **工作范围**：实现 `ui-case-design`、`ui-design-review`；按来源分级生成 case/assertion，映射至 Playwright 测试。先做静态与依赖校验，再由独立上下文按 D1–D10 评估。默认最多 3 次完整评估，保存每轮差异和问题。
- **交付物**：候选/获批修订、结构化评估记录、执行门禁函数及负面样例；评估结果只能通过指定评估调用路径登记。
- **验收**：无依据预期、恒真/空断言、遗漏关键主链等样例被退回；合理样例可通过。缺来源或连续无改善可阻塞。未批准、摘要变化、缺依赖的资产即使 Agent 请求执行也被门禁拒绝。断言自检能在隔离副本中的合理错误结果下失败。
- **阻塞处理**：只阻塞受影响集合，同时保留原范围分母；不能用达到循环上限替代批准。仅源码设计通过与运行就绪分开记录，后者仍需当前环境/定位证据。

### UI-07 正式执行与原始证据采集

- **依赖/输入**：UI-06 的获批修订与 UI-04 的当前预检。
- **工作范围**：实现 `ui-test-run`，冻结计划实例、版本、数据和角色，通过 Playwright Test 启动新 run。首期默认不自动业务重试；关键 assertion_id 使用 step/附件及最小 reporter 映射。
- **交付物**：执行入口、冻结计划、原生结果、attempt、证据索引、实际命令/退出码及清理记录。
- **验收**：首次正式执行从新 context 和新准备数据开始，不沿用录制末态。真实通过、断言失败、启动异常、超时和取消均可区分；每个已启动实例可关联 run/case/attempt。证据存在且能读取，不把 runner 启动成功当用例通过。
- **阻塞处理**：启动失败和执行中断保留可得产物；写操作状态不明时标记需要核对，不自动重复提交。任何脚本修复都新建修订并返回 UI-06 对应流程。

### UI-08 确定性统计、归因和结果评估

- **依赖/输入**：UI-07 的计划、原始报告和证据。
- **工作范围**：实现 `ui-result-analysis`、`ui-result-review`；程序逐实例对账并生成统计，Agent 按事实/解释/证据/替代解释/下一动作分析，独立 reviewer 按 R1–R6 核验。落实设计文档的失败动作分流。
- **交付物**：结果解析器、状态映射、分析草稿、结果评估记录、最终或阶段报告、缺陷草稿及回归建议。
- **验收**：计划实例数等于互斥终态数之和；attempt 不作新 case，重试成功不抹除首次失败，分母为 0 显示不适用。错批次截图、计数不一致、失败写成通过、证据不支持根因等被拦截。真实失败且根因未知的完整报告可以通过评估。
- **阻塞处理**：最多 3 次结果评估；缺证据无法补齐则交付标明缺口的阶段报告，不标记完整性已通过。诊断复跑另记 run/attempt；不改写原始结果。

### UI-09 按需 Skill 组合与重启复用

- **依赖/输入**：UI-08；此前实现的六类业务 Skill、共享脚本和持久化产物。
- **工作范围**：实现 `ui-test-workflow` 的简短能力目录及任务选择规则，组合新录制、仅录制、执行已有资产、查看证据、只分析旧 run 等路径。角色按阶段顺序使用，不先建设并发调度器。
- **交付物**：可安装/加载的完整能力包、任务入口、阶段记录及使用说明。
- **验收**：完全退出客户端和相关任务进程后，重开并新建会话可找到有效资产直接执行；日志证明未调用录制/生成阶段，产生新的 run。只分析旧结果不启动浏览器；仅录制在登记后结束。能力缺失/版本不兼容返回明确阻塞；不依赖旧聊天全文。
- **阻塞处理**：有效批准仍须当前环境和数据预检；旧 run 未确定终态时不得重启相同业务动作。完整中断续跑不属于本任务，但必须安全保存与拒绝盲目续跑。

### UI-10 评估校准和完整闭环验收

- **依赖/输入**：UI-09；人工标注的有效/错误样本及隔离测试环境。样本从 UI-06/UI-08 开始积累，本任务集中验收。
- **工作范围**：校准两个 reviewer，保留未参与规则调整的样本；执行下节验收矩阵。使用真实模型和浏览器完成代表性路径，登记模型、Skill、规则和工具版本。
- **交付物**：样本及期望、各轮评估输出、完整证据索引、M3 验收记录、效率基线和已知限制。
- **验收**：确定性负面检查全部通过；关键评估样本各独立重复至少 3 次，关键错误不漏检、理由有依据，合理样本可通过，并如实统计误拒。真实主链完成录制、两次评估、执行和重启复用；失败分支的报告不美化结果。
- **阻塞处理**：任何关键漏检先修复对应规则再重验；真实模型/目标不可用时只登记受控验证完成，M3 保持待验证。样本通过仅对当前范围和版本有效，不宣称消除幻觉。

## 5. P1 与 P2 任务说明

### UI-11（P1）续跑、失败重跑与中断核对

- **依赖**：UI-10。工作包括区分继续未完成、重跑失败、全量重跑；冻结选择集合，登记 parent_run_id，在 case/业务链边界重建状态。
- **交付物**：恢复入口、选择规则、进程/业务状态核对记录、中断处置说明。
- **验收**：分别演练录制中断、执行前中断、写入后结果丢失、执行后分析前中断；已完成阶段不无故重复，未知业务写入先核对；只有失败重跑不能被报告为原计划全绿。
- **阻塞处理**：无法核对副作用时保留“需要核对”，不自动重放；不能以 PID 或浏览器 ref 证明可恢复。不承诺关闭桌面后后台运行。

### UI-12（P1）变更影响、导入迁移与证据维护

- **依赖**：UI-10。工作包括导入已有脚本并建立映射、依赖变更定位、局部补录/重审、资产迁移、保留期与失效证据标记。
- **交付物**：依赖索引、影响清单、导入/迁移说明、证据维护入口。
- **验收**：修改共享 fixture 能找到所有已登记受影响资产；依赖不完整时保守重审，不声称精确增量。搬到新工作目录后资产可执行且不依赖旧 Skill 路径；凭据未随包导出；活跃评估或缺陷引用的证据不自动删除。新部署仍按有效旧用例回归。
- **阻塞处理**：迁移缺依赖返回清单，历史证据丢失标记不可验证；不重新生成全部资产掩盖丢失问题。

### UI-13（P2）隔离后的并行执行与多 Agent 协作

- **依赖**：UI-11、UI-12。优先用 Playwright worker 并行独立 case，再评估按模块并行发现/生成；调度用经兼容验证的 Pi 能力。
- **交付物**：并发限制、资源归属/共享规则、单写者元数据登记、取消及汇总策略。
- **验收**：串行与并行选择集合及统计一致；没有跨 run 数据污染和重复创建；共享账号/对象可降为串行；部分失败不丢其他任务结果。用相同范围实际耗时与资源开销证明收益。
- **阻塞处理**：隔离不足或调度包不兼容则继续串行；不为接入 `pi-subagents` 改变直接 Agent 技术基准，不为每条 case 创建一个 Agent。

### UI-14（P2）多角色、浏览器及其他扩展评估

- **依赖**：UI-10；按需求分别选择多角色、多浏览器、已确认视觉基线、变更选择或后续接口/UI 联动。不是一次全做的开发包。
- **交付物**：被选扩展的独立小计划、实际必要的 schema/用例更新及验收样例。
- **验收**：扩展范围、证据及统计维度明确；仍经过设计和结果评估；原 P0 路径回归通过。
- **阻塞处理**：没有真实需求或确认基线时保持未开始；不因框架可扩展就提前建设所有能力。

## 7. 每项任务的实施与完成规则

1. 开始前读取任务依赖、相关设计、当前源码与测试，确认实际版本和差距；按第 2.1 节先检索、复用已有选型记录，必要时联网核实，不要把计划里的能力当作现成功能。
2. 只实现该任务必要范围。优先调用 Pi 扩展、包、Skills、MCP 和成熟项目能力；Skills 负责使用方法与判断，确定性脚本负责必要的业务门禁、存储关联和结果适配，成熟工具负责浏览器与执行。新增界面优先使用现有组件或兼容的成熟组件库。
3. 为门禁、状态、统计、恢复等关键逻辑准备有意义的正反例；低影响文字修改只检查文档。协议 mock 与真实外部验证分别记录。
4. 依据变更运行项目实际检查：TypeScript/核心逻辑使用 `npm run check` 与相关测试，客户端交互接入按需运行 `npm run test:electron`；包内检查在建立真实命令后登记，不虚构已有命令。
5. 更新任务状态与证据表、相关操作文档，补充复用来源、版本、验证证据及必要自建理由；确认功能验收和复用约束均满足后才标完成。保留用户无关修改，按仓库规范创建本地提交，不自动推送。

状态只用：未开始、进行中、阻塞、待验证、已完成。开发完成但缺真实环境证据时使用待验证；必需依赖未完成不能宣称对应里程碑已完成。阻塞记录缺什么事实/环境、影响哪些任务及哪些独立工作仍能继续，不因局部阻塞停止全部工作。
