更新：2026-10-21。按 UI-10 → UI-11 → UI-12 顺序实施，复用 Pi 原有工具/阶段持久化、Playwright 原生 grep、Node 文件 API、Git 和现有摘要门禁，不增加调度平台或界面。

## UI-11 续跑与失败重跑

`recoveryPlan` 基于父 run 冻结计划和原生结果选择 case：resume 仅未启动；rerun-failed 仅 failed/flaky；rerun-all 重新选择同一获批资产全量，即使父批次只为子集。`UiRunService.start` 请求绑定 parent_run_ref，保存 selection.json、parent_run_id，并使用原生 grep 选择完整 case/业务链。从新 context/数据初态开始，不恢复临时浏览器对象。标题不能唯一筛选则拒绝。新报告保留父 ID 和原范围限制，不能将子集通过替代原全量失败，不合并部署版本。

`UiWorkflowService.resumeTask` 在校验既有产物与当前能力后继续原阶段，不回退 completed_stages、不清除预算、不复活终态。已执行后中断可继续 analyze；录制 partial 继续保留日志/业务归属，不能直接交接或盲目接着点击。未知写入/活跃父批次仍阻塞，缺证据或 PID 消失不能证明安全；没有通用服务端副作用查询能力时明确需要业务核对，不假称全自动恢复。

`tests/ui-testing/recovery.test.mjs` 三项真实 Chromium 专项通过：两个 case 中一个失败后只重跑失败项，子集新批次通过但父失败字节不变；随后全量选择两个 case 并实际通过；同请求只读旧批次。预检身份失败 business_started=false 后以新 context 重建整 case；未知写入不启动浏览器。工作流中断后继续原分析阶段，并核对源 run 引用不变。正式执行与工作流已有 13 项专项同时通过，包含真实保存后中断不重放、旧批次分析不启动浏览器及录制 partial 门禁。

类型检查与构建通过；两个修改 Skill 的 quick_validate 通过。全量回归 103 项通过、6 项外部模型专项默认跳过；新增工作流 rerun-failed 的 start/execute checkpoint 同时通过。


## UI-12 变更影响、导入迁移与证据维护

既有工作流 Skill 按需调用 `ui_asset_maintain`，薄工具复用 TypeScript AST、原生 Git diff/未跟踪文件、Node 文件 API 及当前 ArtifactStore 摘要/门禁。impact 输出登记依赖闭包、命中及不完整问题；不完整时保守重审，不宣称未知代码没有影响。inspect-import 只返回脚本摘要、已有静态测试标题/行号和动态标题待核对项，后续复用 ui-case-design 建立来源/断言/步骤映射，再评估/诊断，不另建一套生成器。

export 将显式引用闭包及版本写入 `qa/ui-transfers/<id>`，包在业务索引目录之外，避免文件包中的 manifest 被当成已登记资产。拒绝私有认证/模型/配置文件和绝对模块导入，不导出私有批准/会话。import 在新工作区预查全部文件摘要，缺失依赖返回清单，不覆盖同路径不同内容；迁移的私有执行/评估元数据不接受。保留来源、fixture/helper、配置模板和数据规则，目标重新审查/诊断；不按新部署行为改旧预期。普通 putFile 对业务元数据的禁止覆盖规则保持有效，迁移文件使用仅新建/同字节复用的路径检查，不放宽原写入门禁。

audit-evidence 持久化保留期审计与不可核验标记，原始 run/report 字节不变。仍被已登记 run/评估/报告引用的证据默认保护；没有可信外部缺陷关闭状态时不假定可以删除，不自动清理任何证据。缺失历史文件不靠重生成全部资产掩盖。

`tests/ui-testing/maintenance.test.mjs` 三项首轮真实专项通过：修改同一共享依赖找到两个相关资产，依赖缺失即使变更清单无关仍要求重审；导出后在新目录导入，故意缺少脚本先返回依赖清单，补齐后重新批准/诊断，原目录临时移走后仍实际 Playwright 执行退出 0；删除历史 trace 后审计标记不可核验且所有引用证据受保护、未删除任何文件。真实 Pi/Skill 工具调用与私有配置拒绝导出专项已通过，全量回归 107 项通过、6 项外部模型默认跳过。新增普通文件名下认证状态识别后，类型检查和维护专项 4 项复验通过；另以临时 Git 仓库验证带空格的已跟踪变更及未跟踪文件均被发现、选项注入基准被拒（1 项通过）。因此当前维护专项共 5 项通过。


M4 在当前范围通过：阶段恢复/父子批次分开、失败与全量选择、共享依赖影响、导入后重审、可迁移依赖与证据保护均有验证。UI-13/UI-14 为按需求触发的 P2，本轮不引入多 Agent 调度或扩展浏览器矩阵。人工效率基线仍由用户允许待补；未知业务写入继续需要业务核对，外部缺陷引用状态未接入时证据不自动删除。
