# 项目目录与模块开发规范

更新：2026-10-20。唯一工程为 `agent-client/`，技术基准始终为 **Pi Agent SDK + Electron + TypeScript**，执行核心直接使用 `pi-agent-core.Agent`。

## 按功能增加代码

| 功能 | 放置位置 | 对应验证 |
|---|---|---|
| Agent 执行、提示模板 | `main/agent/`，消息展示在 `renderer/features/chat/` | `tests/agent/` |
| 历史、分支、会话管理 | `main/sessions/`；涉及已加载 Agent 生命周期由 `AgentHost` 协调；界面在 `features/sessions/` | `tests/sessions/` |
| 提供商、模型配置、思考强度 | `main/models/`、`features/models/`；Agent 当前状态在宿主中设置 | `tests/models/`、`tests/workspace/session-policy.test.mjs` |
| 工作区路径、工具权限、系统沙箱 | `main/workspace/`、`features/workspace/` | `tests/workspace/` |
| 输入交互 | `features/composer/`；跨会话草稿和发送状态由 `app.ts` 协调 | Electron 输入回归 |
| 系统窗口和退出 | `main/index.ts` | Electron 退出/取消回归 |
| 新主进程能力 | 业务放所属功能模块，在 `shared/types.ts`、preload、`ipc/register.ts` 增加明确方法 | 对应模块与 IPC 校验 |

## 模块边界

1. 新功能先确定归属；在现有功能目录增加文件，避免把全部业务追加到 `app.ts`、`index.ts`。只在实际需要时建立新的功能目录，不先建空壳。
2. `app.ts` 管理应用状态并组合功能；功能视图接收会话快照，控制器通过明确回调返回结果，避免功能模块互相读取全局状态或循环导入。
3. renderer 不引入 Electron、Node 或 Pi SDK，全部系统能力经过 typed preload；main 校验来源、参数和路径，不能依赖下拉框限制代替权限检查。
4. SDK 负责 Agent 循环与工具调度；权限接入使用公开 `operations` / `spawnHook`，持久化复用 SDK 的 `SessionManager`，不维护另一套格式。
5. 样式放 `renderer/styles/` 对应功能文件；`styles.css` 仅组织导入，响应式覆盖最后加载。HTML 的元素 ID 与功能控制器一起修改。
6. 使用明确函数名、格式化代码和适当中文注释，解释边界或原因。保持单向依赖，不创建无用途的通用抽象。
7. 测试按功能放到 `tests/<模块>/`，共享受控服务仅在 `tests/support/`。更新操作指南与技术设计的相关章节，再运行检查。

## 验证命令

在 `agent-client/` 执行 `npm run check`、`npm test`、`npm run test:electron`。`npm run package` 生成 macOS 内部验证应用；对打包结果运行 `tests/electron/flow.mjs` 时通过 `PI_AGENT_EXECUTABLE` 指定应用可执行文件。

`npm run dev` 仍然先构建再启动 Electron，无热更新。重启时完全退出旧窗口，避免单实例机制唤起旧版本。模型和真实历史在 `~/.pi/agent`，不属于工程整理范围。
