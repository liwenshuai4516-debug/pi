# UI 设计评估与运行登记验证

更新：2026-10-21。实现状态以 [实施计划书](./UI测试能力实施计划书.md) 为准。本文区分机制验证、真实模型冒烟和仍待 UI-10 的重复校准。

## 验证范围

`tests/ui-testing/design.test.mjs` 使用真实 TypeScript compiler API、Pi Agent、原生工具注册和 Chromium。受控协议模型只提供预定响应，用于核对上下文隔离、工具交接及程序门禁，不作为语义质量证明。

| 检查 | 证据与成功标准 |
|---|---|
| 静态设计 | 选定场景覆盖、case/test/assertion 唯一映射；编译、依赖版本、共享 helper、配置及本地 extends 纳入摘要；常量、空断言、跳过和不可解析脚本被拦截 |
| 独立评估 | 新 Agent、无工具、无生成者历史；读取原始来源及实际输出 schema；D1–D10 完整评估 |
| 原文引用 | 优先选择程序提供的 anchor_id，还原为真实 FileRef/quote 后核验；伪造片段、错引文及无效结构拒绝，错误输出返回已保存证据引用 |
| 有限修订 | 退回后新修订重评通过；最多三次、无改善阻塞；异常消耗调用预算且不自动批准 |
| 诊断 | 候选与预期不变；正常对照通过，隔离错误副本的指定 expect 步骤失败；报告与 trace 可读。诊断显式 `formal_run:false` |
| 产品缺陷 | 可选正常应用副本做正对照，当前目标独立身份/初态预检；不把当前产品业务通过作为脚本运行登记的前提 |
| 持久化与去重 | 请求先登记再操作；相同请求不再启动浏览器，输入冲突及并发拒绝；新 Agent 可以只查询旧诊断 |
| 未知执行 | 取消或结果不明保留 unknown；换请求 ID 不能重放；启动意图、PID/进程令牌、原始输出和输入引用保留供后续核对 |
| 可信登记 | 只有指定诊断调用路径登记证明；直接写项目 JSON 或底层诊断结果不放行；脚本、配置、证据或实际诊断实现变化使旧证明失效 |

运行证明只保护本工作流入口，不是隔离任意 shell/扩展的安全沙箱。正式执行由 UI-07 创建新批次并重新预检当前环境、认证和数据。任意远端部署与源码一致性仍须项目提供依据。

## 真实模型冒烟与已发现问题

命令：先 `npm run build`，再运行 `PI_UI_DESIGN_LIVE=1 node --test --test-name-pattern="UI-06 live" tests/ui-testing/design.test.mjs`。只复制模型配置到临时私有目录，使用当前配置的 `deepseek / deepseek-v4-pro`；无写入/执行工具。业务来源和原始响应保存到 `evidence/ui-testing/ui-06/<时间标识>/`，认证文件不复制到证据目录。

另一次测试准备失败来自 HTTP 响应变量遮蔽评估回调，在真实模型调用前终止；已重命名变量并以专项回归复验，不计为模型误拒或通过。

最近一次完整受控回归：`npm run check`、`npm run build` 通过；`node --test tests/*/*.test.mjs` 为 76 项通过、2 项外部模型测试未启用。覆盖拒绝检查项转为保留原始证据的阻断问题、同模块未知诊断阻断、无关模块不受阻及缺范围旧记录的保守阻断。两份修改后的 Skills 通过 skill-creator 的 `quick_validate.py`；这些检查不能替代真实模型语义验收。

这些记录说明真实模型可能误拒、输出不合规或给出与代码相矛盾的理由。通过单次冒烟不能宣称评估已无幻觉；UI-10 仍须对关键样本独立重复至少三次，统计关键漏检、合理样本误拒与证据错误，不向评估者提供标准答案。
