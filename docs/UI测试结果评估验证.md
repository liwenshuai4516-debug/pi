# UI 统计、失败分析与结果评估验证

更新：2026-10-21。对应 UI-08，整体进度见[实施计划书](./UI测试能力实施计划书.md)。UI-09 的按需工作流、UI-10 的模型重复校准和 P1 恢复维护仍须分别验收。

## 实现与复用

复用 Pi 1.2.0 的 package、扩展注册、Skill 加载和直接 Agent；Playwright Test 1.62.1 提供原生 JSON 报告、step、attempt、截图、trace 与清理附件。Ajv 校验结构，proper-lockfile 4.1.2 协调私有评估登记，现有 ArtifactStore 保存不可变产物。不新增浏览器控制器、测试引擎、模型执行循环、MCP 桥接、数据库或报告管理界面。

`results.ts` 从冻结计划逐实例对账，保留原生状态和全部尝试。程序统计模块、模块内功能、优先级、oracle、启动实例与稳定通过率；本批次资产的候选和设计评估、功能清单与未探索缺口另列，缺信息不填零。失败缺 trace 仍是失败并标记证据缺失；passed 缺关键断言到达记录不能认定业务通过。附件同时核对 run、case、attempt 的收集登记。

`analysis.ts` 将观察事实、解释、支持证据、替代解释与下一动作分开，程序重算统计并检查分析覆盖和证据归属。`result-review.ts` 以独立无工具 Agent 评估 R1–R6，原始来源与引文可追溯。程序阻断不能被模型批准覆盖；每批次最多三轮、失败调用计预算、重复请求不重放、无改善可提前阻塞。私有批准绑定报告和规则；报告/来源/证据变化后不沿用旧批准。

交付的 Markdown 附评估记录及所评估报告摘要。缺陷及回归建议是未提交、未执行的结构化草稿；脚本、环境、产品和缺证据分别路由。partial 交付明确标识完整性未通过，不能当完整报告批准。

## 验证范围

`npm run check`、`npm run build` 与完整回归已执行。受控回归 **92 项通过、3 项外部模型测试默认未启用**；新增 `results.test.mjs` 和 `result-review.test.mjs` 共 8 项受控检查，另有独立开关的真实模型冒烟。

| 检查 | 已核验行为 |
|---|---|
| 分母与 attempts | 首败后成功为 flaky，不增加 case 数；全部跳过时稳定通过率不适用；互斥状态与计划数一致 |
| 原生状态与断言 | expected-failure 不算稳定通过，关键断言步骤缺失拒绝业务通过；计划外及缺失实例显式披露 |
| 真实 runner | 正常目标得到 passed；有缺陷目标真实断言失败，原生退出码、trace 和失败步骤保留；解析不再次启动浏览器 |
| 统计篡改 | 算术不一致、重复 instance 和形式上平衡但违背原生事实的状态改写被拒绝 |
| 证据归属 | 外批次截图不进入分析，同批次错 instance 的原生附件不成为有效证据；删 trace 使批准失效但失败计数不变 |
| 独立评估路径 | 假 approved 产物无法取得私有批准；新服务实例可读取真实批准；独立 Agent 不接收分析者历史或工具 |
| 循环与交付 | 退回、修订、重评保留历史；错误引文和无效 JSON 消耗预算；无改善阻塞；错误报告和 partial 即使模型批准也不能完整交付 |
| Pi Skill 真实调用 | parse → save-analysis → draft-report → 独立 review → deliver，浏览器请求数保持不变 |

两个新增 Skill 均通过 `skill-creator/scripts/quick_validate.py`。文档路径、引用与差异检查按仓库规则核验。

## 真实模型冒烟与限制

以隔离配置调用 `deepseek / deepseek-v4-pro`，思考关闭，单次限时 120 秒；不复制认证至证据目录。命令：

```sh
PI_UI_RESULT_LIVE=1 node --test --test-name-pattern='UI-08 live' tests/ui-testing/result-review.test.mjs
```

证据目录 `evidence/ui-testing/ui-08/1792560114937/`、`1792560265527/`、`1792560444657/` 均保存输入、原文、评估和来源：真实 UI 失败且根因 unknown 的报告获批，无依据确认数据库死锁的报告被退回或阻塞。最后一轮覆盖新增的 attempt 归属核验和原始设计评估输入。不同报告的同一批次评估沿用历史，不能伪装为相互独立的模型质量样本。

这是机制和代表性样本的冒烟验证，不是任意真实项目的质量保证。受控协议回复只验证工具链和门禁；上述冒烟也不代替 UI-10 每类关键样本至少三次的独立校准。模型未直接查看二进制图片或 trace，不宣称做过视觉核验；文件存在、摘要和归属由程序检查。环境、角色、业务需求和部署版本仍以被测项目提供且已声明的范围为限，不能从 UI 失败证明服务端内部根因。
