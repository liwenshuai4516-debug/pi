## 3. 逐任务执行规范

### T00：建立工作副本与可核对基线

- **关联**：全部 B 功能；N01。输入为用户确认的本地 `pi-web-main` 与 source-baseline.json。
- **工作**：记录源目录版本、文件指纹和用户已有改动；在指定实施目录准备独立工作副本。没有 Git 元数据时不虚构 commit，使用指纹记录；不移动或覆盖原始资料目录。
- **工作**：核对 67 个现有 API、入口组件、设置页和实际测试脚本。补充功能表遗漏，标注“原有”“桌面差异”“新需求”。不把缺少预装依赖视为功能不存在。
- **允许修改**：实施副本的基线说明、测试记录；此时不改业务源码、不添加 Electron 架构。
- **产出**：实际实施路径、源码变化清单、B01–B37 验收记录空表、临时测试项目约定。
- **验证**：基线引用可定位，版本与原 pi 依赖一致，所有发现均分类；源码漂移已解释。
- **完成条件**：基线与工作目录明确，无将 AQA/另一个 pi-web-ui 当成本项目的混淆。
- **停止条件**：源项目被替换、用户修改归属不明或实施目录不可用时，先说明具体阻塞；不得自行重建替代项目。

### T01：固定运行时与构建方式

- **关联**：N01/N08；B21/B24/B25/B29/B30。
- **工作**：按现有锁文件准备依赖并运行未改动版本的 lint、类型和单元测试；记录环境相关失败，不用升级依赖解决未知问题。
- **工作**：选择兼容的精确 Node、Electron、electron-builder 版本；记录选择依据、下载来源、校验方式、支持的 macOS 与架构。明确壳依赖和 Node 后端依赖不共用自动 native rebuild 目标。
- **建议**：桌面入口与 preload 可用 CJS，加必要类型声明；若采用 TypeScript 编译，复用已有工具，不为少量启动代码引入第二套前端构建框架。
- **允许修改**：桌面依赖与锁文件、必要构建/类型检查配置、版本说明。不得漂移原 7 个 pi 依赖、Next 或 React。
- **产出**：版本冻结记录、原始测试基线、实际可运行的桌面开发/验证脚本；新脚本写入 package.json 后才可在报告中当作可用命令。
- **验证**：独立 Node 能解析所需运行依赖；npm/npx 定位成功；原有脚本仍存在。
- **完成条件**：版本可复现、依赖差异可解释。版本号仍是占位符时不得通过 G0。

### T02：验证生产后端、可写目录与动态依赖

- **关联**：N01/N08；B21/B24/B25/B29/B30/B34。
- **工作**：在隔离发布目录执行现有生产构建；用独立 Node 启动普通 Next 服务，初期可用浏览器验证，不能只验证 next dev。
- **工作**：按 01 第 4 节尝试分离布局；从干净运行目录首次启动，再复用启动；验证 manifest 密钥轮换、缓存、public、动态 SDK、WASM、PTY 和 npm/npx。
- **允许修改**：desktop/build、backend hooks、必要的生产资源收集配置；不改 Next/pi 包源码，不通过关掉模块消除加载错误。
- **产出**：唯一布局决策、资源清单与构建标识、首次/后续启动测量、发现的签名及路径问题。
- **验证**：删除测试副本的开发依赖后依然启动；从只读安装资源读取、可写目录写入；移动应用后资源路径能修复；用代表性 MCP 和 codemode 验证动态加载而不只是 require 成功。
- **完成条件**：布局不依赖开发机路径、用户预装 Node 或临时权限修复。完整后端副本若作为备选，应记录成本后冻结，不能无说明切换。
- **停止条件**：只能靠修改 SDK、补丁 Next 私有实现或永久复制开发环境才能工作，则 G1 阻塞。

### T03：认证、就绪与启动失败处理

- **关联**：N04/N06；B22/B28/B34/B36。
- **工作**：实现单实例、启动状态、端口选择、01 第 5 节的身份核对、现有 Web 登录与正确 partition Cookie；引导失败可重试。
- **允许修改**：desktop/main 认证/启动模块、必要的精确 health 路由及 proxy 分支、环境传递测试。业务 API 不迁移。
- **产出**：启动状态机、身份核对 ADR、错误分类与故障注入用例。
- **验证**：端口被占、探测后被抢占、假服务返回 200/错误签名、慢启动、进程提前退出、旧 Cookie、无认证请求、正确 Cookie 的 SSE/上传。
- **验证**：health 无 AgentSession 副作用；Web 模式 health 不可用；Host/Origin 检查保留；密钥不出现在日志、URL、renderer 全局或项目命令环境。
- **完成条件**：不会打开陌生监听服务，不先向未确认服务泄露登录密码；完整 fetch/SSE 登录链成立。

### T04：工作窗口、预览、下载与受限桥接

- **关联**：N02/N03/N05；B01/B08/B15/B18/B19/B22/B32。
- **工作**：窗口注册表区分工作/预览；实现两个真实工作窗口共享一个后端；保留普通点击与新标签行为差异；实现来源检查与导航分流。
- **工作**：安装标准编辑菜单与快捷键；键盘不抢终端/输入法；下载使用正确认证会话，保留文件名与 Blob 语义。
- **允许修改**：desktop/main 与 preload；必要的 SessionSidebar 桌面文案/窗口分支、版本/诊断入口；不重写聊天路由与状态。
- **产出**：窗口类型规则、preload 类型表、导航允许清单、两窗口及预览验证记录。
- **验证**：A 打开会话 B 和新项目窗口；A 原草稿/页签保持；B URL 目标正确；共享主题生效；同会话不产生第二个后端会话实例。
- **验证**：HTML 导出、PDF 页码、原文件下载、Blob、外链和 OAuth；外部页/预览不能调用业务 IPC；预览关闭不会退出应用。
- **完成条件**：原新标签能力得到等价承接，没有用“全部在当前窗口打开”偷减功能。

### T05：退出、异常断开与进程归属

- **关联**：N03/N06；B08/B09/B21/B29/B31/B34。
- **工作**：实现一次性退出协调；多窗口收集退出提示所需最少信息，取消不破坏窗口状态。非最后窗口关闭不杀后端，最后工作窗口/Cmd+Q 统一退出。
- **工作**：正常清理优先、明确超时；主进程异常断开时 Node hooks 触发自清理。记录只管理自己启动的进程，不使用系统级按名称 kill。
- **允许修改**：desktop 生命周期模块、backend hooks；现有 Pi Web 清理缺陷若被复现，先写复现与最小修复依据，不升级成新任务调度器。
- **产出**：超时依据、正常/慢关闭/强制退出/父进程崩溃记录、残留进程检查方式。
- **验证**：SSE、运行任务、终端长命令、MCP、子智能体场景；与 CLI 原 5 秒计时不冲突；存在另一个用户 CLI 时不被误杀。
- **完成条件**：规定的受控正常退出用例通过，异常边界明确。无法可靠清理的第三方 daemon 不伪装成受控进程已终止。

### T06：接入桌面模式与原有通知

- **关联**：N03/N07；B01/B08/B32/B33/B36/B37。
- **工作**：显式桌面能力标记；只为 PWA/Web Push、更新、窗口及通知加入必要分支。保留原主题、语言、布局和设置入口。
- **工作**：既有完成/等待输入通知及提示音在桌面可用；禁用 SW 后 push 初始化必须立即完成；多窗口去重、点击定位按既有事件关联会话。
- **允许修改**：PwaRegistration、push-client、browser-notifications、必要的 AppShell 与版本设置分支、desktop 通知模块、现有语言资源。
- **产出**：桌面/Web 差异表、通知处理路径、权限拒绝行为与三种语言文字。
- **验证**：聚焦/失焦/最小化、两窗口、权限允许/拒绝、已停止任务、扩展等待输入；Web 原 PWA 分支回归。
- **完成条件**：不是只让聊天看起来可用；既有通知不能被归入 P1 而遗漏。

### T07：会话、对话和扩展交互回归

- **产出**：B01–B15 的分项证据、消息/数据一致性记录、缺陷清单。

- **允许修改**：测试和桌面导航/资源路径适配；不新增文件编辑或 Git 提交功能。
- **产出**：各文件类型与下载记录、授权边界用例、PTY 与 worktree 生命周期证据。
- **验证**：生产包内而非开发模式；目标 Native 模块、无用户 Node、真正文件落盘、外部变更刷新、关闭后的受控进程清理。

### T10：错误恢复、数据与诊断
