## 1. 保留规则

B01–B35 是首版工作台保留要求，优先级 R0；B36 为 Web 专属能力的保留边界，B37 为应用发布模式的等价替换。R0 不按“功能复杂”降低优先级。任何表中省略的现有交互仍默认保留，Agent 在 T00 补充发现记录，不因没有单列就删除。

每项分别记录三种结果：原 Web 基线、Electron 开发环境、安装后的生产包。前两者通过不自动推出第三者通过。外部 Provider/MCP 的集成范围写明实际服务及版本，不声称覆盖全部第三方实现。

## 8. API 与数据兼容检查

`source-baseline.json` 包含 67 个现有 API 路由及显式导出的方法。发布前比较当前列表：删除路由、减少方法、变更响应或事件字段都必须定位至具体 B 编号并解释；未经用户批准不得作为桌面化改变。

不要求所有源码哈希保持不变；已批准桌面分支会改变相关文件。但每个差异必须归属 T 任务；未归属差异、pi 依赖漂移、demo 替代业务、接口整体迁移均阻止验收。

所有 API 请求都通过现有业务授权链；Electron 本机窗口不能绕过文件根、项目信任、Web 请求校验和扩展响应规则。新增 health 的有限豁免单独测试，不能借它调用业务动作。
